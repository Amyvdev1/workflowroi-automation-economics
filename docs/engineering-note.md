# When the right automation recommendation is “do not automate”

By Amy Villa

Automation has an implementation bill, an operating bill and a failure bill. Ignoring any one of them can make an attractive demo look like a profitable system.

WorkflowROI models manual, partially automated and AI-assisted workflows separately. Tasks outside the adoption fraction stay manual. Reviewed automated tasks consume review labor, and review prevents errors only at the assumed detection rate. Maintenance recurs every week; implementation is charged once.

Expected error loss is probability times economic consequence. It is not an observed incident count. Weekly risk-adjusted savings compares operating cost plus expected error loss with the fully manual baseline. Payback exists only when weekly savings are positive.

The recommendation considers a one-year horizon. A system can have positive weekly savings and still fail to repay its implementation cost in that horizon. Zero volume, zero adoption and unknown tool/model prices are handled explicitly rather than producing infinity, NaN or invented savings.

Sensitivity varies adoption and error cost independently. It is a decision aid, not a statistical confidence interval. The next useful experiment is a small measured pilot that replaces assumptions about review time, adoption and unresolved errors with evidence.
